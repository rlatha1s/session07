# 실습: OpenAI API를 활용하여 나만의 캐릭터 챗봇 만들기

Next.js App Router와 TypeScript로 만드는 작은 캐릭터 챗봇입니다. **치이카와**와 대화하며, 캐릭터 설정과 OpenAI API 연결 과정을 배웁니다. 먼저 실행한 다음 **`src/prompts/character.ts`부터 수정하세요.**

## 1. 설치하고 실행하기

Node.js 20.9 이상과 npm이 필요합니다. 프로젝트 폴더에서 실행하세요.

```bash
npm install
cp .env.example .env.local
```

`.env.local`을 열어 발급받은 키와 모델명을 입력합니다.

```dotenv
OPENAI_API_KEY=여기에_본인의_API_키_입력
OPENAI_MODEL=gpt-5.5
```

실제 키는 `.env.local`에만 보관합니다. 이 파일은 Git에서 제외됩니다. 키에 `NEXT_PUBLIC_` 접두사를 붙이거나 화면 코드에 입력하지 마세요. API 사용에는 계정의 사용 가능 잔액과 모델 접근 권한이 필요합니다.

```bash
npm run dev
```

브라우저에서 <http://localhost:3000>을 엽니다. 포트가 사용 중이면 터미널에 표시된 주소를 확인하세요. 환경변수를 바꾼 뒤에는 개발 서버를 종료하고 다시 실행합니다. 키 없이도 화면과 빌드는 확인할 수 있지만, 전송하면 서버 설정 오류가 표시됩니다.

배포용 빌드를 로컬에서 실행하려면 다음 순서로 진행합니다.

```bash
npm run build
npm run typecheck
npm start
```

## 2. 실습: 나만의 캐릭터로 바꿔보기

`src/prompts/character.ts`의 `character` 객체를 아래와 같이 수정해 봅니다.

| 항목            | 바뀌는 부분                   | 실습 예시                                                 |
| --------------- | ----------------------------- | --------------------------------------------------------- |
| `name`          | 화면 이름, 캐릭터의 자기 인식 | 치이카와 → 하치와레                                       |
| `description`   | 화면 소개와 응답 지침         | 밝고 다정하며 친구를 좋아하는 하치와레                    |
| `greeting`      | 새 대화의 첫 인사, 말투 예시  | 안녕! 오늘은 뭐 하고 있었어?                              |
| `roleAndWorld`  | 역할과 세계관                 | 동굴에서 생활하며 친구들과 풀 뽑기와 토벌을 하는 하치와레 |
| `personality`   | 상대를 대하는 태도            | 긍정적이고 사교적이며 친구를 잘 챙기는 성격               |
| `speakingStyle` | 존댓말, 어휘와 말투           | 친근한 반말, 감탄과 질문을 자주 사용                      |
| `rules`         | 답변 길이·구조·행동           | 짧고 밝게 답하고, 사용자의 말에 적극적으로 반응하기       |

`public/character.jpg`를 다른 파일로 대체하여 캐릭터의 프로필도 바꾸어 보세요.

`buildCharacterInstructions()`는 이 설정을 한 개의 지침 문자열로 만듭니다. 화면이나 API 코드에 별도의 긴 프롬프트를 복사할 필요가 없습니다. 첫 인사는 API 응답이 아닌 고정된 환영 문구이며, 실제 대화 기록과 분리됩니다.

설정을 저장한 뒤 **브라우저를 새로고침해 변경된 표시 정보를 받아 오고 새 대화를 시작하세요.** 개발 중에는 화면 상태가 유지될 수 있으므로 자동 갱신에만 의존하지 마세요. ‘새 대화’ 버튼도 기록을 지우지만 서버 페이지의 정보를 새로 가져오지는 않습니다. `npm start`로 실행 중이면 수정 후 다시 빌드하고 서버를 재시작합니다.

추천 실습 순서:

1. 이름·소개·첫 인사를 바꾸고 화면을 확인합니다.
2. 역할·말투·규칙을 바꾸고 같은 질문에 대한 답변을 비교합니다.
3. "밤만쥬 먹을래?", "맛있어?"와 같은 연속된 메세지를 보내 대화 문맥을 확인합니다.
4. ‘새 대화’ 후 같은 질문을 보내 이전 기록이 사라진 것을 확인합니다.

캐릭터 행동은 모델이 생성하므로 지침이 매번 완벽하게 지켜지는 것은 아닙니다.

## 3. 코드 읽는 순서와 데이터 흐름

```text
character.ts ── 표시 정보 ──> page.tsx ──> Chat.tsx
      │                                     │
      └── instructions ──> openai.ts         │ 사용자 입력 + 성공한 대화 기록
                              ↑             ↓
                         /api/chat <── POST 요청
                              │
                         OpenAI Responses API
                              │
                       { reply } ──> React 상태 ──> 말풍선
```

| 파일                        | 역할                                              |
| --------------------------- | ------------------------------------------------- |
| `src/prompts/character.ts`  | 캐릭터 설정과 지침 생성. 서버 전용                |
| `src/app/page.tsx`          | 서버에서 이름·소개·첫 인사만 골라 전달            |
| `src/components/Chat.tsx`   | 대화·입력·대기·오류 상태와 전송·초기화 이벤트     |
| `src/app/api/chat/route.ts` | JSON 요청 검증, 서버 함수 호출, 안전한 오류 응답  |
| `src/lib/openai.ts`         | 서버 환경변수, 공식 SDK 호출, 답변 완성 여부 검사 |
| `src/lib/chat.ts`           | 공용 메시지 타입, 제한, 실제 값 검증              |
| `src/app/layout.tsx`        | 공통 HTML과 한국어 설정                           |
| `src/app/globals.css`       | 모바일 대응 화면                                  |
| `public/character.jpg`      | 캐릭터 프로필 이미지 경로                         |

화면의 `handleSubmit` → 서버의 `POST` → `generateReply` → `setMessages` 순서로 읽어 보세요. 브라우저는 OpenAI에 직접 요청하지 않습니다. `server-only`가 붙은 파일을 클라이언트에서 가져오면 빌드 오류가 발생하여 서버 코드의 잘못된 사용을 알려 줍니다.

서버는 매 요청에 캐릭터 `instructions`와 대화 `input`을 별도로 전달합니다. 브라우저가 보내는 역할은 `user`와 `assistant`만 허용하며, `system`·`developer` 메시지는 400 오류로 거절합니다. 허용된 대화 텍스트 역시 신뢰할 수 없는 사용자 입력이며, 이 역할 검사가 모든 프롬프트 공격을 막아 주는 것은 아닙니다.

## 4. 상태와 오류 처리 이해하기

- 성공한 질문과 답변만 `messages`에 저장합니다. 새 질문은 응답 대기 중 별도 말풍선으로 보여 줍니다.
- 실패하면 대기 말풍선을 제거하고 오류를 표시하며 입력을 보존합니다. 같은 ‘보내기’ 버튼으로 다시 시도합니다.
- 빈 입력과 중복 전송은 화면과 이벤트에서 차단합니다. 줄바꿈은 입력창에서 하고, 전송은 버튼으로 합니다.
- ‘새 대화’는 요청을 취소하고 기록을 지웁니다. 이전 요청의 응답도 무시합니다. 취소가 이미 시작된 외부 API 처리를 반드시 중단시키는 것은 아닙니다.
- 새로고침하면 React 상태가 초기화됩니다. DB나 로컬 저장소에는 대화를 저장하지 않습니다.
- 요청당 최대 40개 메시지, 메시지당 4,000자, 전체 24,000자입니다. 첫 인사는 개수에서 제외됩니다. 글자 수는 JavaScript 문자열 길이 기준으로 일부 이모지는 여러 자로 셉니다. 제한에 도달하면 기록을 조용히 자르는 대신 새 대화를 안내합니다.
- 환경변수 누락은 503, 잘못된 입력은 400, 사용량 제한은 429, 외부 호출 실패·빈 답변·미완성 답변은 502로 반환합니다. 내부 오류 원문은 반환하지 않습니다.
- 외부 호출은 30초 제한이며 자동 재시도를 하지 않습니다. 최대 출력은 1,200토큰입니다. 미완성 답변은 정상 말풍선에 추가하지 않습니다.

코드의 `[확장 포인트]`를 검색하면 DB 저장, 스트리밍, 여러 캐릭터 선택, 사용량 분석을 어디에 연결할지 볼 수 있습니다. 이 기능들은 이번 실습에 구현하지 않았습니다. 로그인·업로드·음성·관리자 기능도 포함하지 않습니다.

## 5. 직접 점검하기

| 확인할 상황                           | 기대 결과                                       |
| ------------------------------------- | ----------------------------------------------- |
| 빈 입력 또는 공백만 입력              | 전송되지 않음                                   |
| 전송 버튼을 연속 클릭                 | 한 요청만 전송, 대기 표시                       |
| 정상 질문 후 후속 질문                | 이전 사용자·캐릭터 메시지를 함께 전송           |
| 키 누락 또는 API 실패                 | 오류 표시, 입력 보존, 성공 기록에 추가하지 않음 |
| 응답 대기 중 ‘새 대화’                | 기록 초기화, 이전 응답이 나타나지 않음          |
| 4,000자 초과 메시지를 API에 직접 요청 | 400 오류                                        |
| `system` 또는 `developer` 역할 요청   | 400 오류                                        |
| 모바일 너비                           | 입력창·전송·초기화 버튼 사용 가능               |

브라우저 개발자 도구의 Network에서 `/api/chat` 요청을 열면 `messages` 배열을 확인할 수 있습니다. OpenAI 키나 캐릭터 전체 지침이 요청에 들어 있지 않은 것도 확인해 보세요.

## 제작 시 검증 결과

- `npm run build`, `npm run typecheck` 통과.
- 실행 중인 서버에 직접 요청하여 잘못된 JSON, 메시지 누락·공백, 허용하지 않은 역할, 개수·길이 제한, 환경변수 누락 처리를 확인했습니다.
- Chrome에서 빈 입력 차단, 실제 키 누락 오류 후 입력 보존을 확인했습니다. **테스트용 응답**으로 전송·대기·답변 표시·후속 대화 기록 전달·요청 중 초기화를 확인했습니다.
- SDK를 테스트 대역으로 바꾸어 빈 답변·미완성·실패·길이 초과 응답 거절과 설정 변경 시 지침 재생성을 확인했습니다. 실제 API 응답 검증은 아닙니다.
- 375px 모바일 화면을 확인했고, 브라우저 JavaScript 번들에 서버 전용 캐릭터 지침이 포함되지 않은 것을 확인했습니다.
- **GPT-5.5 실제 API 호출 검증 완료:** 입력한 키로 로컬 `/api/chat`에서 두 차례 HTTP 200 응답을 확인했습니다. 첫 질문에 캐릭터 모아로 답했고(약 3.2초), 후속 질문에서 앞서 말한 선호 색상인 초록색을 정확히 참조했습니다(약 1.8초). 기존 30초 제한과 `max_output_tokens: 1200` 설정에서 완료됐습니다. 이 결과는 두 가지 간단한 질문에 대한 확인이며 모든 질문의 품질·지연을 보장하지는 않습니다.

## 공식 문서

공식 문서에서 `instructions`와 `input`을 분리하고 `output_text`를 읽는 SDK 사용법을 확인했습니다. 응답 저장을 비활성화하는 `store: false`를 사용합니다. [Responses API 안내](https://developers.openai.com/api/docs/guides/migrate-to-responses)

기본 모델 `gpt-5.5`는 텍스트 입출력과 Responses API를 지원합니다. 다른 모델을 사용하려면 `.env.local`의 `OPENAI_MODEL`을 바꾸고 해당 모델의 지원 기능을 확인하세요. [모델 공식 문서](https://developers.openai.com/api/docs/models/gpt-5.5)
